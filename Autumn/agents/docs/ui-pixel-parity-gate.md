# UI 1:1 视觉还原门禁

## 1. 目标

Autumn 的前端界面必须按已确认效果图 1:1 还原。效果图不是视觉灵感板，而是页面实现合同。任何页面、弹窗、面板、组合状态和交互状态，只有通过 UI/UX Agent 的视觉验收后，才允许进入下一轮开发或测试。

## 2. 适用范围

该门禁适用于所有用户可见 UI：

- 主页 / 项目列表。
- 新建项目空态。
- 编辑器工作台。
- 故事板、媒体文件、时间线、文档面板。
- 右侧对话流。
- 模型、Skill、Agent、素材选择弹窗。
- 加载、空态、错误、生成中、已完成、hover、selected、disabled 等状态。
- 暗色模式和白天模式。

## 3. 开发前置条件

前端工程师 Agent 开发任一 UI 前必须拿到：

- 暗色参考效果图。
- 白天参考效果图。
- 页面 / 状态编号。
- 交互说明。
- 视觉标注或可从效果图拆出的标注。
- 验收清单。

缺少暗色或白天任一主题时，该任务只能进入原型开发，不能进入正式 UI 开发。

## 4. 1:1 还原项目

必须逐项还原：

- 页面布局：三栏比例、面板位置、面板宽高、底栏高度、滚动区域。
- 控件尺寸：按钮、图标按钮、输入框、卡片、弹窗、轨道、缩略图、头像、标签。
- 字体：字体族、字号、字重、行高、文字颜色、占位文字颜色。
- 色调：背景色、面板色、渐变、强调色、选中态、hover 态、禁用态。
- 线条：边框粗细、边框颜色、分割线透明度、虚线样式。
- 形态：圆角、阴影、模糊、透明度、噪点 / 质感背景。
- 间距：页面外边距、面板内边距、组件间距、文字与图标间距。
- 交互：点击、切换、展开、折叠、输入、滚动、上传、发送、停止生成、反馈评分。
- 状态：默认、hover、selected、active、disabled、loading、empty、error、success、generating。

## 5. 验收方法

1. 前端工程师 Agent 使用相同 viewport 和主题启动页面。
2. 使用 Playwright 截取实现截图。
3. 与参考效果图进行人工对照和必要的截图叠图 / 像素 diff。
4. UI/UX Agent 输出 `PASS` 或 `REDO`。
5. `REDO` 必须回到前端工程师 Agent 返工，直到 UI/UX Agent 给出 `PASS`。

辅助量化建议：

- 关键布局位置偏差：0-2px。
- 控件宽高偏差：0-2px。
- 字号 / 字重 / 行高：必须一致。
- 边框粗细 / 圆角：必须一致，最多允许 1px 渲染误差。
- 颜色：必须使用设计 token，截图取样 RGB 误差不超过 3。
- 整体像素差异：只能作为辅助指标，不得替代人工验收。

最终验收口径：肉眼可见差异零容忍。

## 6. 证据产物

每个 UI 任务验收必须沉淀：

- 参考效果图路径。
- 实现截图路径。
- 暗色模式验收结论。
- 白天模式验收结论。
- 差异清单。
- 返工记录。
- UI/UX Agent 最终签字结论。

建议路径：

```text
src/assets/ui-mockups/        # 参考效果图
src/assets/generated-ui/       # 前端实现截图、diff 图
agents/runs/<run-id>/          # 验收报告
```

## 7. 流程阻塞规则

- UI/UX Agent 未 `PASS`：前端任务不得标记 DONE。
- UI/UX Agent 未 `PASS`：测试工程师 Agent 不接收正式验收。
- UI/UX Agent 未 `PASS`：项目经理 Agent 不推进下一轮。
- UI/UX Agent 未 `PASS`：总架构师 Agent 必须调度返工，而不是继续拆新 UI 任务。

## 8. 当前项目状态修正

当前已经开发出的界面只能视为“功能原型已跑通”。在完成效果图 1:1 还原并通过 UI/UX Agent 验收前，不能视为最终 UI 交付。
