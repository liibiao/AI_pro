# 多 Agent 软件工程方法论

## 1. 基本理念

Autumn 使用“产品定义 -> 架构约束 -> 并行开发 -> 独立验收 -> 记忆沉淀”的开发方法。

## 2. 分层交付

每个功能都必须分别明确：

- 产品层：用户价值和验收标准。
- 交互层：界面结构、状态和用户路径。
- 架构层：模块边界、接口和数据模型。
- 前端层：组件、状态、service、adapter。
- 后端层：API、数据库、任务、权限。
- 测试层：用例、缺陷、验收结论。
- 管理层：进度、日志、风险、记忆。

## 3. 质量优先级

1. 正确性。
2. 可维护性。
3. 可扩展性。
4. 用户体验。
5. 开发速度。

速度不能凌驾于架构边界和验收质量之上。

## 4. 拆分粒度

任务必须小到可以独立验收：

- 一个任务只交付一个明确能力。
- 一个任务必须有明确输入和输出。
- 一个任务必须能被测试工程师 Agent 验收。

## 5. 变更控制

任何影响架构、接口、数据库、UI 主流程、验收标准的变更都必须记录：

- 原因。
- 影响范围。
- 替代方案。
- 最终决策。
- 后续风险。
