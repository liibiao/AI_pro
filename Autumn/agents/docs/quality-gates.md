# 质量门禁

## 1. 需求门禁

进入开发前必须满足：

- 有明确用户价值。
- 有功能范围。
- 有验收标准。
- 有依赖和风险。
- 涉及 UI 的需求有交互说明。

## 2. 架构门禁

进入开发前必须满足：

- 业务域明确。
- 分层位置明确。
- 模块依赖明确。
- 数据模型明确。
- 前后端接口契约明确。

## 3. 开发门禁

开发完成必须满足：

- 类型完整。
- 无核心 `any`。
- 无反向依赖。
- UI 不直接调用 API。
- 复杂逻辑不写在 JSX 中。
- 关键状态完整。

## 4. UI 1:1 视觉还原门禁

所有涉及 UI 的任务，进入测试前必须满足：

- 已存在暗色和白天两套参考效果图。
- 前端已按同 viewport、同主题输出实现截图。
- 页面布局、交互逻辑、字体字号、字重、行高、色调、颜色、控件尺寸、边框粗细、线条颜色、圆角、阴影、间距和状态反馈均与效果图 1:1 对齐。
- UI/UX Agent 已对暗色和白天两套主题出具 `PASS`。
- 如 UI/UX Agent 出具 `REDO`，项目经理 Agent 必须阻塞推进，总架构师 Agent 必须调度前端返工。

功能跑通但视觉未通过，只能标记为 `FUNCTIONAL_READY / UI_REDO`，不得标记 DONE。

## 5. 测试门禁

验收前必须满足：

- lint 通过。
- build 通过。
- 关键单元测试或手动验证通过。
- 浏览器关键路径检查通过。
- 涉及 UI 的任务已经通过 UI/UX Agent 1:1 视觉验收。
- 缺陷无 P0/P1 阻塞。

## 6. 发布门禁

发布前必须满足：

- 所有目标任务为 DONE。
- 所有用户可见 UI 均有 UI/UX Agent 视觉验收通过记录。
- 测试工程师 Agent 给出通过结论。
- 项目经理 Agent 更新日志和记忆。
- 总架构师 Agent 输出最终交付确认。
