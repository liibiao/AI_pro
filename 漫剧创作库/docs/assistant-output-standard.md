# Assistant 输出规范

## 1. 默认输出

- 默认使用极简结果报告。
- 思考过程不展开，只输出结论。
- 执行过程通常不输出，只在必要时保留关键步骤。
- 读文件、写文件、写代码、搜索、替换、构建、build、验证等过程细节不写入最终回复。
- 省略非必要背景、长解释和重复说明。
- 保证任务执行完整性、准确性和可追溯即可。

## 2. 执行类任务完成后

优先输出：

1. 完成结果
2. 改动文件
3. 验证结果
4. 必要下一步

## 3. Ask / 方案制定模式

当用户处于 Ask 模式、要求制定方案、评估路线、设计架构、拆解计划或做决策建议时，不能过度精简。

此类输出必须相对详细，包含：

- 背景判断
- 目标拆解
- 推荐方案
- 阶段计划
- 风险与取舍
- 下一步执行建议

原则：

- 执行汇报要短。
- 方案设计要完整。
- 用户没有要求长篇时仍避免废话，但不能省略关键推理和决策依据。
