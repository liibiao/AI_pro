# quality-control-skill — 质量控制技能

## 用途
执行阶段门禁、自查评分、审校报告输出与返工建议。

## 触发条件
当任何阶段完成后需要做质量检查和放行判断时调用。

## 输入
- 当前阶段的所有产出文件
- `phase-gate-checklist.md`
- 前一阶段的放行记录

## 输出
- 门禁检查结果
- 质量评分
- 返工建议（如需要）

---

## 方法论

### 一、阶段门禁检查

#### Phase 1：定位与立项
- [ ] 平台已明确
- [ ] 目标读者已明确
- [ ] 一句话故事核清晰
- [ ] 卖点能在 1-2 句说清
- [ ] 没有明显题材漂移
> 放行标准：通过 4 项以上，且故事核清晰。

#### Phase 2：设定与结构
- [ ] 主角目标明确
- [ ] 对立关系明确
- [ ] 关键冲突链成立
- [ ] 结构不存在明显空档
- [ ] 结尾回收方向已预设
- [ ] 角色圣经已可用
> 放行标准：关键冲突链与结构主轴稳定。

#### Phase 3：正文生产
- [ ] 当前章节有推进
- [ ] 当前章节有人物动作与信息变化
- [ ] 章节末尾有钩子
- [ ] 无大段无效抒情
- [ ] 人设未漂移
- [ ] 信息释放节奏合理
> 放行标准：章节有效推进，读者有继续读的动力。

#### Phase 4：编辑改稿
- [ ] 语言收紧
- [ ] 节奏明显优于初稿
- [ ] 重复信息已删除
- [ ] 开头更强
- [ ] 结尾更有回响
- [ ] 文风统一
> 放行标准：文风统一、可读性提升明确。

#### Phase 5：终审
- [ ] 逻辑闭合
- [ ] 时间线合理
- [ ] 角色称谓一致
- [ ] 设定无冲突
- [ ] 包装与正文一致
> 放行标准：可进入发布或归档状态。

### 二、质量评分体系

总分 100 分：

| 维度 | 分值 | 评分要点 |
|------|------|---------|
| 故事核 | 15 | 冲突是否清晰、卖点是否明确 |
| 结构 | 20 | 节奏是否稳定、钩子是否到位 |
| 角色 | 20 | 人设是否立体、弧线是否成立 |
| 正文质量 | 25 | 语言是否有力、场景是否生动 |
| 一致性 | 10 | 逻辑/时间线/设定是否自洽 |
| 平台适配 | 10 | 字数/风格/包装是否匹配 |

### 三、返工判定

| 等级 | 条件 | 处理 |
|------|------|------|
| **放行** | 总分 ≥ 80，无 P0 问题 | 进入下一阶段 |
| **小修放行** | 总分 ≥ 65，无 P0，有 P1 | 标注问题，局部修改后放行 |
| **打回** | 总分 < 65 或有 P0 | 退回对应阶段重做 |

### 四、返工指令格式

```markdown
## 返工指令

- 退回阶段：Phase [X]
- 退回给：[Agent]
- 退回原因：[具体原因]
- 必改项：
  1. [xxx]
  2. [xxx]
- 可不改项：
  1. [xxx]
- 修改后是否需要复审：是/否
```
