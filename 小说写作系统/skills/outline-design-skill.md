# outline-design-skill — 大纲设计技能

## 用途
设计故事骨架、阶段推进、章节规划与核心事件分布。

## 触发条件
当需要从故事核/灵感推导出完整的结构大纲和章节计划时调用。

## 输入
- 故事核（一句话）
- 目标平台与字数
- 题材类型
- `project.json`

## 输出
- `03-outline/story-architecture.md`（粗纲/骨架层）
- `03-outline/chapter-plan.md`（章节简表）
- `03-outline/detailed-outline.md`（细纲/弧线层）
- `03-outline/chapter-outline-chXX.md`（章纲/单章蓝图）

---

## 方法论

### 一、大纲设计五步法

#### Step 1：确定主轴
一句话回答：主角从 A 状态到 B 状态，核心驱动力是什么？

#### Step 2：划分阶段
根据结构模式划分 3-5 个大阶段：
- **起势**（10-15%）：建立世界、引入冲突、钩住读者
- **加压**（25-35%）：持续升级困难、制造紧迫感
- **中段转折**（40-50%）：最大危机或真相揭露
- **高潮**（70-85%）：最终对决或最大反转
- **收束**（90-100%）：回收伏笔、情绪落地

#### Step 3：填充关键事件
每个阶段必须有：
- 1 个核心事件（不可删除）
- 1 个情绪高点（爽点/泪点/燃点）
- 1 个钩子（驱动读者进入下一阶段）

#### Step 4：章节拆分
将每个阶段拆分为具体章节：
- 短篇（8000-15000字）：8-15 章，每章 800-1500 字
- 中篇（30000-80000字）：30-60 章，每章 1000-2000 字
- 长篇（100000+字）：100+ 章，每章 2000-3000 字

#### Step 5：标注钩子与卡点
- 每章结尾标注钩子类型（悬念/反转/升级/情感）
- 标注付费卡点位置（如适用）
- 标注可删除章节（压力测试）

### 二、章节计划表格式

```markdown
| 章节 | 标题 | 核心事件 | 推进项 | 钩子 | 字数 |
|------|------|----------|--------|------|------|
| Ch01 | xxx  | xxx      | 主线   | 悬念 | 1200 |
```

### 三、大纲自检清单

- [ ] 主轴一句话能说清
- [ ] 每个阶段有独立高潮
- [ ] 中段有持续加压机制
- [ ] 钩子分布均匀
- [ ] 结尾有回收
- [ ] 删掉任何一章都会损失信息

### 四、细纲设计（弧线层）

> 细纲是粗纲（story-architecture）和章纲（chapter-outline）之间的桥梁。粗纲说"这段要发生什么"，细纲说"这段具体怎么发生——场景怎么排列、信息怎么释放、情绪怎么递进"。

#### 4.1 细纲的粒度

| 项目类型 | 细纲单元 | 覆盖章节数 |
|----------|----------|-----------|
| 短篇（< 15000字） | 全书一份细纲 | 全部章节 |
| 中篇（30000-80000字） | 按幕/阶段分份 | 每5-10章 |
| 长篇（100000+字） | 按卷分份 | 每卷（10-15章） |

#### 4.2 细纲必须包含的要素

**1. 情节线梳理**
```
主线：[本段核心推进]
支线A：[推进内容] ── 交汇点：[与主线的交织位置]
支线B：[推进内容] ── 交汇点：[与主线的交织位置]
```

**2. 场景序列**
按时间顺序列出本段所有场景：
```
场景1：[地点] · [在场角色] · [核心事件] → [状态变化]
场景2：...
场景3：...
```

**3. 信息释放计划**
```
已释放信息：[读者目前已知的]
本段新释放：
  - 信息①：[内容] · 释放方式：[事件/对话/环境/行为] · 释放时机：[哪个场景]
  - 信息②：...
本段埋伏笔：
  - 伏笔①：[内容] · 计划回收：[哪个阶段]
```

**4. 情绪弧线**
```
开局情绪：[读者进入本段时的情绪状态]
情绪递进：平静 → [转折] → 紧张 → [加压] → 高潮 → [释放] → 余韵
本段情绪峰值：[最大爽点/泪点/燃点位置]
本段情绪低谷：[最压抑/最绝望位置]
```

**5. 角色弧线追踪**
```
[角色A]：进入状态[X] → 关键选择[场景N] → 退出状态[Y]
[角色B]：进入状态[X] → ...
```

**6. 爽点与钩子分布**
```
爽点：
  - 爽点①：[类型·打脸/逆转/升级/恋爱/智斗] · 位置：[场景N] · 预期强度：[1-5]
钩子：
  - 开篇钩子：[内容] · 类型：[悬念/反转/危机]
  - 中段抓点：[内容] · 类型：[悬念/反转/危机]
  - 段尾钩子：[内容] · 类型：[悬念/反转/危机]
```

#### 4.3 细纲→章纲的拆分规则

细纲完成后，按以下规则拆分为单章章纲：
1. **每个场景独立成章**的前提：该场景能支撑 1000 字以上且有独立的"进入→冲突→变化→钩子"
2. **多个小场景合并成章**：当单个场景不足 800 字时，2-3 个相关场景可合并
3. **大场景拆分为多章**：当单个场景超过 3000 字时，按情绪转折点拆分
4. **每章必须有**：至少 1 个冲突 + 至少 1 个信息变化 + 章尾钩子

#### 4.4 细纲自检

- [ ] 情节线是否有主线推进？（不是纯日常流水账）
- [ ] 信息释放是否≤2个/章？（不信息倾销）
- [ ] 情绪是否有起伏？（不是一条直线）
- [ ] 场景序列是否有因果逻辑？（不是随机拼接）
- [ ] 角色是否有状态变化？（进入≠退出）
- [ ] 爽点分布是否均匀？（间隔≤5章）

### 五、章纲设计（单章蓝图）

> 章纲是写正文前的最后一步规划。Draft-Writer 拿到章纲后应该能直接开写，不需要再"想这章要写什么"。

#### 5.1 章纲必须包含的要素

**1. 章节元信息**
```
章节号：ChXXX
所属卷：VX / 阶段名
预计字数：XXXX字
POV视角：[角色名]
```

**2. 承接与衔接**
```
承接上章：[上章结束时的状态/悬念/情绪]
本章目标：[读者读完这章后，应该知道什么/感受什么]
为下章铺垫：[本章结尾要埋的钩子/伏笔]
```

**3. 场景拆分**
```
场景1（约XX字）：
  地点：
  在场角色：
  核心事件：
  五拍微结构：进入→冲突触发→信息推进→情绪升级→段尾钩子
  POV：

场景2（约XX字）：
  ...
```

**4. 信息管控**
```
本章释放信息：
  - [信息1] · 释放方式 · 释放时机（场景X）
本章埋设伏笔：
  - [伏笔1] · 计划回收位置
```

**5. 情绪节拍**
```
本章情绪曲线：[开局] → [中段] → [高潮/转折] → [收束]
章尾钩子：[类型] · [具体内容]
```

**6. 角色状态**
```
[角色A] 进入状态：[情绪/处境] → 退出状态：
[角色B] 进入状态：[情绪/处境] → 退出状态：
```

#### 5.2 章纲的触发时机

| 类型 | 时机 | 范围 |
|------|------|------|
| 短篇 | 全部章纲在 P3b 一次性产出 | 全部章节 |
| 中篇 | 全部章纲在 P3b 一次性产出 | 全部章节 |
| 长篇 | 每卷章纲在该卷开始前产出（P3b 分批） | 当前卷 |

#### 5.3 章纲自检

- [ ] POV 是否明确且一致？（不中途切换视角）
- [ ] 字数预算是否合理分配到各场景？（不头重脚轻）
- [ ] 是否有冲突？（没有冲突的场景要合并或删除）
- [ ] 章尾是否有钩子？（读者有理由读下一章）
- [ ] 信息释放是否≤2个？（不信息倾销）
- [ ] 与上章/下章的衔接是否清晰？（不脱节）

### 六、大纲层级总览

```
粗纲（story-architecture）
  ├─ 一句话主轴
  ├─ 结构模式选择
  ├─ 阶段/卷划分
  └─ 关键转折点
      ↓
细纲（detailed-outline）
  ├─ 情节线梳理（主线+支线+交汇点）
  ├─ 场景序列（全部场景排列）
  ├─ 信息释放计划（释放+埋伏笔）
  ├─ 情绪弧线（起伏+峰值+低谷）
  ├─ 角色弧线（进入→选择→退出）
  └─ 爽点/钩子分布
      ↓
章纲（chapter-outline-chXX）
  ├─ 章节元信息（POV/字数/所属卷）
  ├─ 承接与衔接（上章→本章→下章）
  ├─ 场景拆分（每个场景的五拍微结构）
  ├─ 信息管控（释放+埋伏笔）
  ├─ 情绪节拍（曲线+章尾钩子）
  └─ 角色状态（进入→退出）
      ↓
场景卡（scene-card）
  ├─ 基本信息（地点/时间/角色）
  ├─ 场景目标（核心事件+推进项）
  ├─ 五拍微结构（详细拆分）
  └─ 自检（损失/变化/情绪）
      ↓
正文
```
